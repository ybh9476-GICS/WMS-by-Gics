# WMS by Gics

`index.html`을 Edge 또는 Chrome에서 열면 에디터가 바로 실행됩니다. 실행을 위한 설치, 로그인, 로컬 서버, 인터넷 연결은 필요하지 않습니다.

## 로컬 서버로 테스트하기

`start-local-editor.cmd`를 더블클릭하면 전용 서버를 실행하고 기본 브라우저에서 **http://127.0.0.1:4174/** 를 엽니다. 서버 방식에는 Node.js가 필요하며, 추가 패키지 설치는 필요하지 않습니다. 터미널에서는 이 폴더에서 `npm run dev`로 실행할 수 있습니다.

서버는 이 프로젝트 폴더의 최신 파일을 매번 읽습니다. 코드를 저장한 다음 브라우저를 새로고침하면 반영되며, 별도 복사·빌드·서버 재시작은 필요하지 않습니다. 자동으로 화면을 새로고침하는 기능은 포함하지 않습니다. 서버 자체 코드를 바꾸면 서버를 재시작하세요.

서버는 이 컴퓨터에서만 접속할 수 있고, 대영포장 서버와 다른 4174번 포트를 사용합니다. 4174번 포트가 이미 사용 중이면 기존 서버를 종료하거나 덮어쓰지 않고 안내 후 멈춥니다. 실행 창에서 `Ctrl+C`를 누르면 서버를 종료합니다.

서버는 에디터 파일을 읽어 제공하며 도면·기준정보를 프로젝트 파일에 자동 기록하지 않습니다. `http://127.0.0.1:4174/`와 HTML 직접 실행은 브라우저 저장 공간이 서로 다릅니다. 두 실행 방식 사이의 작업 이동은 `.gics`·`.tbl` 파일을 사용하세요. 서버 이용 시에는 위 주소를 계속 사용하는 것이 좋습니다.

## 포함 기능

- 평면도: 도면 탭, 랙·통로·컨베이어·설비 배치, 속성 편집, 실행 취소·다시 실행, 확대·축소, `.gics` 열기·저장
- 기준정보: 기존 13개 시트 + `3D 연결`, 셀·행·열 편집, `.tbl` 열기·저장, Excel 가져오기·내보내기
- 3D View: 활성 도면의 창고·랙·통로·설비 및 연결된 재고 표시, 카메라 투영·시점 전환, 회전·확대/축소, 물류 흐름 모의 운행과 일시정지·재개
- 평면도 상단의 새로 불러오기 버튼: 이 프로젝트의 기준정보에서 랙타입을 읽습니다.

대영포장 프로젝트의 WMS by Gics 에디터·3D View와 파일에 포함된 기준정보 사본을 복제했습니다. 기획서 사이트, 로그인, 메뉴 관리는 포함하지 않습니다. 원본 프로젝트의 브라우저에만 저장되어 있는 개인 작업은 복사하지 않았습니다. 그런 작업은 원본에서 `.gics` 또는 `.tbl`로 저장한 후 여기에서 열 수 있습니다.

## 3D View 사용

오른쪽 위의 큐브 모양 `3D View` 버튼으로 이동합니다. 3D 화면 오른쪽 위의 평면도·기준 정보 버튼으로 돌아올 수 있습니다. 평면도의 도면 탭·편집 내용·실행 취소 기록은 화면을 오가도 유지됩니다.

3D 화면은 **평면도 에디터의 활성 도면**에서 크기·위치·각도·랙 규격·간격·분기 경로·장비 배치를 읽습니다. 도면을 수정한 뒤 3D로 이동하면 파일 저장 전 편집 내용도 반영됩니다. 그리는 중인 경로는 먼저 완성하거나 취소해야 합니다. 다른 도면 탭을 선택하면 해당 도면이 표시됩니다. 빈 도면은 빈 창고로 표시됩니다.

품목·재고·로케이션 용량·설비 사용 여부와 속도·통신 상태·작업지시·운영 경로는 이 사이트의 **기준 정보 모드**에서 읽습니다. Google Sheets나 대영포장 프로젝트에 접속하지 않습니다. 모드 진입 또는 3D 새로 불러오기로 반영되며, 다른 창의 변경을 운행 중에 자동으로 합치지 않습니다.

`3D 연결` 시트는 불러올 때 자동 보완되며 다음 기준으로 사용합니다.

| 열 | 입력 내용 |
| --- | --- |
| 도면 이름 | 특정 도면 이름 또는 모든 도면에 적용하는 `*`. 같은 대상은 특정 도면 설정이 우선합니다. |
| 대상 코드 | 평면도에 표시된 랙·장비 코드 |
| 구역코드 | 랙이 속할 `구역설정`의 코드. 미지정 랙도 표시됩니다. |
| 기준정보 코드 | 장비에 연결할 `설비 마스터` 코드. 비어 있으면 도면의 대상 코드를 사용합니다. |

기존 랙배치의 랙·구역 연결은 최초 보완 때 옮기며 원래 시트는 삭제하지 않습니다. `평면도`, `랙배치`, `평면도 검증`은 3D 배치에 사용하지 않는 보관용 시트입니다. 로케이션 마스터에 `랙열번호` 열을 추가하며 빈 값은 1열입니다. 사용자 셀을 덮어쓰지 않고 필요한 열을 끝에 추가합니다. 사용안내의 기존 기본 문구는 새 연결 방식에 맞게 갱신합니다. 이 보완은 다음 기준정보 수정·파일 저장에 포함됩니다.

도면에서 로케이션을 생성했다면 **로케이션 코드가 정확히 일치할 때만** 재고와 용량을 연결합니다. 생성하지 않았다면 로케이션 마스터의 랙·랙열·베이·단·깊이 위치를 사용합니다. 범위를 벗어나거나 코드가 맞지 않는 재고는 표시하지 않고 이유를 안내합니다. 중복 코드나 중복 위치는 오류로 안내합니다. 랙타입 마스터의 변경은 배치된 랙의 규격을 자동 변경하지 않습니다. 평면도에서 해당 규격을 적용해야 3D에 반영됩니다.

물류 장비는 도면의 위치·크기·회전으로 표시합니다. 기본 모의 운행은 **지정 경로 반복 주행**입니다. 장비 속성에서 AMR·Forklift AMR에는 `T`, 셔틀에는 `GR` 경로를 지정하세요. 경로의 가장 가까운 지점에서 시작하며 끝점에서는 돌아오고 연결된 분기도 반복 주행합니다. 설비 속도가 있으면 사용하고 없으면 1 m/s로 표시합니다. 경로 미지정이나 장비보다 좁은 경로는 하단에 이유를 표시합니다. 이 모드는 이동 경로 확인용이며 작업지시·재고 처리·충돌 예약을 실행하지 않습니다.

평면도와 3D의 중앙 화면 하단에 재생(삼각형)·일시정지(두 막대)·정지(사각형) 아이콘을 독립된 세 버튼으로 표시합니다. 버튼 위치와 아이콘은 바뀌지 않으며 현재 상태를 배경·테두리와 색상으로 강조합니다. 마우스를 올리면 기능 설명이 나타나고, 키보드와 화면 읽기 프로그램에서도 각 버튼을 구분할 수 있습니다. 3D 화면을 열기만 하면 준비 상태이며 재생을 눌러 시작합니다. 일시정지는 현재 위치를 유지하고, 재생은 이어서 실행합니다. 정지는 위치·시간·모의 재고·스캔 이력을 초기화한 뒤 대기합니다. 완료 후 재생을 누르면 처음부터 실행합니다. 화면을 전환해도 장비 위치·시간·선택한 운행 방식이 유지되고, 평면도에도 움직이는 장비가 표시됩니다. 입력 오류나 경로를 그리는 중에도 일시정지·재생·정지는 즉시 작동합니다. 원래 배치 위치는 흐리게 표시합니다. 운행 방식을 변경하면 현재 위치에서 멈추고, 안내에 따라 재생을 누를 때 초기 배치와 기준정보 재고로 새 운행을 시작합니다. 도면 수정·도면 탭 변경·기준정보 변경 반영 시 기존 운행을 종료하고 초기화 안내를 표시하며, 선택한 운행 방식은 유지합니다. 숨겨진 3D 화면은 그리기를 멈추고 운행 계산만 이어갑니다.

하단에서 **입출고 작업지시**를 선택하고 재생하면 물류 흐름 모의를 사용할 수 있습니다. 두 운행 방식 모두 장비 중심을 지정 경로의 가까운 지점에 맞춰 시작합니다(원본 배치는 유지). `운영 경로`의 D·B·S 코드를 도면 코드에, AMR 코드를 연결된 설비 마스터 코드에 맞추세요. 컨베이어의 구간별 진행 방향도 적용하며, 화물 폭에 맞는 도크↔버퍼 경로만 검사합니다. 사용하지 않는 좁은 컨베이어는 작업을 막지 않습니다. 통로 폭, 연결, 사용 여부, 통신, 속도, 로케이션 용량이 맞지 않으면 대상 코드와 원인을 하단에 표시합니다. 실행 가능한 작업이 없으면 `실행 불가`, 모든 작업이 끝나면 `완료`로 정지합니다. 정지 후 재생하거나 완료 후 재생하면 모의 재고·장비 위치·진행 시간·스캔 이력을 초기화하여 다시 실행합니다. 도크 → 컨베이어 → 버퍼 → AMR → 스테이션 → 셔틀 → 랙(출고는 반대 순서)을 사용하며 공유 경로와 인계 구역을 작업 단위로 예약합니다.

모의 운행은 화면 안에서만 실행되며 기준정보의 실제 재고와 도면을 덮어쓰지 않습니다. 브라우저 새로고침 또는 3D 새로 불러오기는 운행을 초기화합니다. `.gics`·`.tbl` 저장 형식과 매번 저장 위치를 선택하는 방식은 유지됩니다. 3D 표시는 도면당 최대 100,000셀입니다.

Three.js 0.185.1을 라이선스와 함께 폴더에 포함했습니다. 로컬 서버와 HTML 직접 실행에서 외부 CDN이나 Google 시트 연결 없이 동작합니다. 3D 표시는 브라우저의 WebGL 2 그래픽 기능이 필요합니다.

## 독립 실행과 저장

모든 실행 파일은 이 폴더 안에 있습니다. 원본 폴더 연결, 바로가기 연결, 원본 Git 이력·원격 저장소, Google 문서 연결은 없습니다. 폴더를 옮길 때는 HTML 하나만 옮기지 말고 `js`, `css`, `data`, `vendor`를 함께 옮기세요.

브라우저 자동 저장도 `gics-standalone-`으로 시작하는 별도 저장 이름을 사용합니다. 이곳의 편집 내용은 대영포장 프로젝트로 반영되지 않습니다. 랙 기준정보를 수정하려면 상단의 기준 정보 버튼을 누르고 `랙타입 마스터` 시트를 편집하세요. 평면도로 돌아와 새로 불러오기를 누르면 목록에 반영되며 이미 배치한 랙의 규격은 유지됩니다.

브라우저나 폴더 경로를 바꾸거나 브라우저 데이터를 지우면 자동 저장 작업을 다시 찾지 못할 수 있습니다. 보관할 도면은 `.gics`, 기준정보는 `.tbl` 파일로 저장하세요. Excel은 기준정보의 값을 교환하는 용도이며 수식 계산 엔진은 제공하지 않습니다.

도면·기준정보·Excel의 저장 버튼을 누를 때마다 파일 이름과 저장 위치를 선택하는 시스템 창을 요청합니다. 이전 저장 파일을 기억해서 창 없이 덮어쓰지 않으며, 취소하면 파일을 기록하지 않습니다. 시스템 저장창을 지원하지 않는 브라우저에서는 자동 다운로드 대신 Edge 또는 Chrome에서 열라는 안내를 표시합니다. 브라우저 작업공간 자동 저장은 그대로 유지합니다.

## 검증

Node.js가 있으면 `npm test`로 회귀 테스트와 독립 저장 테스트를 실행할 수 있습니다. HTML 직접 실행에는 Node.js가 필요하지 않습니다.

2026-10-02 검증 결과:

- 자동 테스트 14개 파일: 도면 형식·배치·분기·설비·기준정보·Excel 처리·저장 충돌·원본 저장 이름 분리·로컬 서버·3D 데이터 변환·운행·스캔 터널·정밀 도면 연결
- Edge의 별도 테스트 프로필에서 인터넷을 차단하고 `file://`로 실제 HTML 실행
- 랙 베이 수 수정, 실행 취소·다시 실행, 새로고침 복원, `.gics` 저장·열기 확인
- 기준정보 셀 수정, 14개 시트의 `.tbl`·Excel 내보내기·가져오기 및 재실행 복원
- 1440px·900px 화면 점검, 외부 요청·누락 파일·JavaScript 오류 없음
- `http://127.0.0.1:4174/`에서도 같은 편집·복원·파일 저장 및 가져오기 브라우저 검증 통과
- 3D: 서버와 오프라인 HTML 직접 실행에서 화면 표시, 카메라 전환·드래그·확대/축소, 검색·선택, 운행 일시정지·재개, 화면 왕복·새로 불러오기, 기준정보 편집 반영과 평면도 실행 취소 기록 보존 확인

브라우저 검증 코드는 `tests/standalone-browser.cjs`입니다. 별도로 Playwright와 Edge가 있는 환경에서 실행하며, Playwright가 다른 위치에 설치되어 있다면 `WMS_PLAYWRIGHT` 또는 `NODE_PATH`로 지정할 수 있습니다. 결과와 화면 캡처는 `output`에 생성됩니다. 테스트는 별도 프로필을 사용하므로 실제 사용자 작업을 변경하지 않습니다.

서버 검증은 `tests/local-server.test.cjs`에서 파일 변경 즉시 반영, 캐시 미사용, 파일 읽기만 허용, 프로젝트 밖 경로·폴더 연결 접근 차단을 확인합니다. 서버를 실행한 뒤 `WMS_TEST_URL=http://127.0.0.1:4174/` 환경 변수를 지정하면 같은 브라우저 검증을 서버 주소로 실행할 수 있습니다.

3D 브라우저 검증은 `tests/warehouse-browser.cjs`이며 같은 `WMS_TEST_URL` 설정을 사용합니다. 환경 변수를 생략하면 인터넷을 차단한 `file://` 실행으로 검증합니다. 결과는 `output/3d-file-checks.json`, `output/3d-server-checks.json`에 기록합니다.

`tests/warehouse-drawing-browser.cjs`는 회전·마진·간격·활성 탭·장비 배치와 연결된 입고 운행, 스캔, 정지, 원본 재고 보존을 검증합니다. `WMS_TEST_OUTBOUND=1`을 지정하면 출고와 역방향 컨베이어를 검증합니다.

`tests/simulation-sync-browser.cjs`는 평면도에서 재생 시작, 두 화면의 위치·시간·정지·운행 방식 동기화, 숨겨진 3D 그리기 중단, 입출고 완료, 원본 데이터 보존과 도면 변경 시 운행 종료를 검증합니다. `tests/warehouse-route-preview.test.cjs`는 경로 끝점 왕복과 분기 반복 주행을 검사합니다.

`tests/simulation-controls-browser.cjs`는 입력 오류 중 정지·재개, 정지 중 모드 변경, 완료 후 재시작, 원본 재고와 스캔 초기화, 중심선 밖 장비, 무관한 좁은 컨베이어, 실제 경로 폭 오류, 빈 작업지시, 도면 변경 안내와 운행 방식 유지를 검증합니다. `WMS_TEST_URL`을 생략하면 오프라인 HTML 직접 실행으로 검사합니다.

3D 외형은 기존 렌더러의 모델 생성 함수를 공유합니다. 랙의 연속 빔, 리프트 프레임, AMR의 차체·마스트·포크, 셔틀 차체·바퀴, 컨베이어 롤러·지지대, 통신 상태 빌보드를 별도 단순 모델로 대체하지 않습니다. 도면의 위치·회전·장비 크기를 적용하고 기존 장비 목록·선택·추적·이력 기능을 사용합니다. 도크 차량과 송장 빌보드도 기존 모델을 사용합니다.

`tests/warehouse-appearance-browser.cjs`는 같은 입력에서 기존 기준정보 경로와 도면 경로의 랙·AMR·셔틀·리프트 정점/부품/재질 및 빌보드 이미지가 일치하는지 비교하고 장비 선택·추적·이력 창을 확인합니다.

컨베이어 연결부는 `js/warehouse-conveyor-layout.js`에서 실제 도면 좌표로 계산합니다. 꺾임·분기·교차·중복 구간의 롤러를 중복 생성하지 않고 측면 프레임은 바깥 둘레에만 배치합니다. 날카로운 모서리는 길이를 제한해 돌출을 방지합니다. 이 계산은 3D 외형에만 적용되며 도면 좌표·운행 연결·진행 방향·저장 데이터는 바꾸지 않습니다. `tests/warehouse-conveyor-layout.test.cjs`는 11가지 연결 형태에서 면 누락·롤러 충돌·통로를 가로막는 프레임을 검사하며, `tests/warehouse-conveyor-browser.cjs`는 실제 브라우저의 수정 전후 비교 화면을 `output/conveyor-*.png`로 저장합니다.

반복 저장·취소·저장창 미지원 환경은 `tests/save-picker-browser.cjs`로 검증했습니다. 자동 브라우저 테스트에서는 시스템 저장창을 대신하는 테스트 함수를 사용하여 저장창 호출 횟수와 출력 파일 내용을 확인합니다. 운영체제의 실제 파일 저장 대화상자와 실제 한글 IME 조합 입력은 검증하지 못했습니다.

## 파일 구성

GR 레일은 `js/warehouse-shuttle-rails.js`에서 연결된 경로의 바깥·안쪽 경계 차이로 만듭니다. 모서리의 안쪽 돌출과 바깥쪽 단절을 없애고 동일한 형상을 각 층에 적용합니다. `tests/warehouse-shuttle-rails.test.cjs`는 직각·사선·분기·폐회로 등의 연결성과 돌출·겹침을, `tests/warehouse-shuttle-rails-browser.cjs`는 실제 3D 형상의 모서리를 여러 층에서 검사합니다.

- `index.html`, `js/standalone.js`, `css/standalone.css`: 독립 실행 시작 화면
- `js/floor-plan-*.js`, `css/floor-plan-editor.css`: 에디터와 데이터 처리
- `js/warehouse-*.js`, `css/warehouse-3d.css`: 3D 화면·모의 운행·로컬 기준정보 연결
- `data/wms-reference-seed.js`: HTML 직접 실행용 기준정보 사본
- `data/wms-reference-seed.json`: 같은 기준정보의 원본 형식 사본; 초기값을 변경할 때 JS 사본도 함께 갱신해야 합니다.
- `vendor`: 로컬 Excel·Three.js 처리 모듈, 라이선스와 출처 안내
- `tests`: 에디터 회귀 테스트와 독립 실행 검증
- `scripts/local-server.cjs`, `start-local-editor.cmd`: 전용 로컬 서버와 더블클릭 실행 파일
